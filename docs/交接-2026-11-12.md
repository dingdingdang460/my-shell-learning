## 4. 云端生成的真实边界（最容易说错的地方，别含糊）

应用里**没有本地模型**，我也不在你的进程里常驻。所以：

| 情况 | 右键点击后发生什么 |
|---|---|
| **没填 API Key**（当前状态） | 立刻写工单到 `%APPDATA%\wallpaper\jobs\queue\<id>.json`，卡片标「生成中」，然后**等外部来取单**。等的是：WorkBuddy 侧（我）出片投进 `videos\`，或配了 `genCmd` 时启动的那个程序 |
| **填了 Key**（`genProvider` + `genApiKey`） | 应用自己 `Submit → 每 5s 轮询 → Download`，全程不需要我，1–4 分钟自动换台，换电脑填别人的 Key 就能用 |
| 两种情况共同点 | 收货逻辑只有一条：`SweepCloudJobs` 每 3 秒扫队列，发现 `videos\<id>.mp4` 存在就 `MarkDone` + `SetMotion(fx=2)` + 若 `pendingCloudId == id` 则 `ApplyItem` 立即换台 |

所以「右键一点就出片」**只有填 Key 才成立**。用户明确说过「算了吧我自用，需要动态视频我让你干活」，所以现在这个半自动状态是他认可的，但**每次汇报都要讲清代价，不能吹成全自动**。

API 价格（已核）：通义万相 `wan2.6-i2v-flash` 720P 约 0.15 元/秒 → 3 秒 ≈0.45 元；火山 `seedance` 约 0.2–0.6 元/秒 → 3 秒 ≈0.6–1.8 元。真人脸会被火山拒。

## 5. 出片的完整流水线（今天验证过的，照抄即可）

平台能力限制（`VideoGen`）：**最短 4 秒**、最长 15 秒、**不能关音轨**（minimax-video-h3 强制带音频）。

```bash
# ① 生成（我这边调用，产出在 _raw\，本机实测 1344x768 / 24fps / 4.46s / 870KB，约 65 积分）
#    image = D:\Wallpaper\images\<id>.jpg，prompt 用 CloudGen.BuildPrompt 那套硬约束
#    （身份不变、镜头完全静止、只让头发衣摆飘、首尾同帧、无水印）

# ② 后处理：去水印 + 压到 3 秒 + 正放倒放做无缝循环 + 剥音轨
py -3.13 tools/video_fix.py "<raw.mp4>" "D:\Wallpaper\videos\_raw\fix-<id>.mp4" --seconds 3
#    水印位置默认按 1344x768 量的（相对坐标 0.007,0.008,0.066,0.060），换服务商要重量一次

# ③ 投放（同盘 mv，原子替换，避免扫到半截文件）
mv "/d/Wallpaper/videos/_raw/fix-<id>.mp4" "/d/Wallpaper/videos/<id>.mp4"

# ④ 3 秒内自动收货，无需点任何东西。核对：
ls "$APPDATA/wallpaper/jobs/queue/"   # 应为空
ls "$APPDATA/wallpaper/jobs/done/"    # 应有 <id>.json
tail -20 "$TEMP/wallpaper-debug.log"  # 应有「到货」「换上新生成的飘动视频」「首帧提交 成功」
```

成品规格：1344×768 / 6.00 秒（3 秒正放 + 3 秒倒放）/ 1.4MB / 无音轨 / 播放器 23fps。

## 9. 踩过的坑（省时间）

1. **截图/点菜单反复失败**：编辑器抢前台，`SetForegroundWindow` 后点击落到编辑器。→ 用第 8 节的应用内自检，别硬刚。
2. **`shot.py` 会自己起一个播放器播硬编码的 `dystopian-city-port.mp4`**，跑完会把桌面壁纸换掉/杀掉播放器。别在正式播放时随手跑。
3. **`tasklist | grep wallpaper` 空了**不等于应用崩了，可能只是刚被 build.bat 杀掉等重启。
4. **微信/第三方下载夹不在 `%USERPROFILE%\Downloads`**：这台机器改到 `D:\下载`，要读注册表 `{374DE290-123F-4565-9164-39C4925E467B}`。
5. **`TextBlock` 有 `LineHeight`，`TextBox` 没有**（编译直接报错）。
6. **改 `.cs` 文件后必须重新 `build.bat` 并重启**，exe 不会热加载。
7. `PIL`/`imageio_ffmpeg` 只在 `py -3.13` 里。
8. 出片模型的硬约束：最短 4 秒、强制音轨 → 后处理一定要 `--seconds 3` + `-an`（`video_fix.py` 已内置）。

## 10. 明天可以继续的（按价值排序）

1. **切 4K / 多屏**：现在片源 1344×768，4K 屏上是放大铺满，会糊。要么 API 侧给更高分辨率（`genResolution` 已支持但未验证），要么出片时按屏幕比例生成。
2. **播放器 23fps → 30fps**：日志显示「近 5 秒画了 119 帧」，`dynamicFps=30` 但实际 23。瓶颈在 MF 解码 + NV12→RGB 的 CPU 转换，可考虑换 `MF_SOURCE_READER_ENABLE_ADVANCED_VIDEO_PROCESSING` 或直接吃 NV12 上屏。
3. **循环首尾**：现在靠 ping-pong（正放+倒放）保证无缝，代价是动作周期变 6 秒、有轻微「来回摆」感。若想纯单向循环，得让模型真的做到首尾同帧，目前不可控。
4. **日常便利功能**（一直没开工）：低电量自动停动态、库内去重、拼音搜索、缓存/代理设置。
5. **引导用户填 API Key**：如果哪天他嫌「排单等我」麻烦，通义 0.45 元/张是最省事的解法，设置页已经能填。
