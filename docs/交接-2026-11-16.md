## 1. 本轮做了什么

只做了需求明确、不依赖架构选择的三项：

1. **功耗守卫**（P1-4）：`app/PowerGuard.cs`。电池供电且电量 ≤ 阈值（默认 20%）
   时暂停播放器解码，插电自动恢复；设置页可改阈值或关掉。台式机永不触发。
2. **全局异常兜底**（P1-5）：界面线程异常接住并继续运行、只提示一次；
   后台线程写 `wallpaper-crash-*.log`。托盘新增「打开日志」。
3. **删除进回收站**（P1-6）：`app/Recycle.cs`，`SHFileOperation + FOF_ALLOWUNDO`；
   回收站不可用时才退回硬删。

顺手修了一个真实缺陷：`--clouddialogtest` 在默认积分通道（`genChannel=buddy`）
下会真弹积分确认框、自检卡死。已把自检里的通道固定为 `api` 并注入弹窗答案。

## 4. 已知坑（新增）

- 跑 `--*test` 前先确认主程序没在运行，否则被单实例锁挡掉、**日志不写**，
  看着像「自检没跑」。跑前把 `TEMP`/`TMP` 指向仓库内 `.selftest-tmp\`。
- `--guardtest` 的回收站断言会把 2 个几十字节测试文件送进系统回收站
  （建在 `.selftest-tmp` 下），清空回收站即可。
- 自检里凡是会走 `RegenCloud` 的，都要注意当前 `GenChannel`：
  积分通道下会进 `StartBuddyGen` 的确认框，必须注入 `SelfTestNoBuddyDialogs`。
- 四个会写真实库/配置的自检（`--deltest / --greettest / --configtest /
  --arrivetest`）默认不跑；`--cloudtest` 会写死工单，永远别跑。
