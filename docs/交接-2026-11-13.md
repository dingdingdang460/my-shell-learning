## 7. 关键实现细节（改之前先看）

1. **搜索三路命中**：标题原文（含译名 `DisplayTitle`）→ 分类中文名（`TagNames.SearchKey`）→ 拼音首字母。
   纯字母才走首字母，中文词直接子串匹配，不做无用计算。
2. **「有飘动视频」筛选**用的是 `App.HasCloudVideo`（静态图且有 `videos\<id>.mp4`），
   **不是** `MotionCapable` —— 后者对视频也返回 true，会把 16 个视频全混进来。
3. **色系先判明暗再判冷暖**：一张深蓝夜景，人第一眼是「暗」不是「冷」。
4. **缩略图缓存键含 `LastWriteTimeUtc.Ticks`**，图被重新下载后自动失效，不会显示旧图。
5. **代理 `Proxy = null` 在 .NET 里表示「不使用代理」**，不是「用系统默认」，这点决定了空配置的行为与以前完全一致。
6. **筛选条只在本地模式显示**（`UpdateBackBar` 里跟着 `showingOnline` 走），在线结果里它筛不到东西。
7. **主窗口多了一行 RowDefinition**：header / backBar / filterBar / cards / status，overlay 的 `RowSpan` 是 5。改布局时别只改一半。

## 12. 云端出片：接上本地动效引擎（11-13 上午，未完成，下午继续）

### 12.1 起因

主人原话：**「生成的视频效果不要整体平移那种，脚本要做到和你花积分生成的视频效果 80% 以上」**。

（ffmpeg `crop` 整数位移 + `eq`），本质还是**整体平移**，离真视频差得远。所以重做。

### 12.2 现在是什么

三层结构：

| 层 | 文件 | 职责 |
| --- | --- | --- |
| 调度 | `tools/gen-motion.ps1` / `.bat` | 读工单、加锁、找 ffmpeg/python、失败标记、写日志 |
| 引擎 | `tools/gen-motion.py` | 按画面内容分区做局部动效，出 1080p H.264 |
| 兜底 | ps1 里的 `Build-Filter` | 找不到 Python 时退回 ffmpeg 平移版（效果弱但不报错） |

引擎做的事（**都是局部运动，不是整图位移**）：

- **天空**：整体缓慢漂移（20px，3 秒一个来回）+ 二维低频形变（云缘翻卷）；
  越靠地平线动得越多（近大远小）。锐利结构（鸟居、电线）用边缘遮罩排除，
  柱子不会被云拖着走 —— 实测放大对比，柱子纹丝不动，云在后面飘。
- **水面/云海**：只在地平线以下 22% 的**中景带**里做，浪涌 + 起伏 + 反光流动；
  近景（草叶、栏杆、被褥）一律不动，避免双影。
- **雨**：两层不同速度的雨丝，速度按 `cycles*(H+len)/T` 取整，保证循环无缝。
- **夜景灯光**：只作用于亮点，按空间相位极轻起伏（不产生几何畸变，判错也不毁画面）。
- **光影流动**：一条很柔的亮带斜着扫过 + 同周期呼吸（screen 叠加，不过曝）。
- **兜底**：既没天空也没水没雨的图（室内/人像），整幅叠 0.7 像素低频微动。

### 12.3 三条硬约束怎么保证

1. **首尾同帧**：所有时间项取 `sin(2πkt/T)`（k 整数），t=T 时回到 0；
   雨丝用 `(y+speed*t) mod (H+len)` 且 speed 取整。
   实测成片首尾 PSNR 41.7dB（≈ 一帧之内的正常差），循环不跳。
2. **不像整体平移**：位移是**逐像素的二维位移场**（`warp()` 双线性采样），
   空间上变化；整体漂移只占一部分，形变占大头。
3. **不能有伪影**：`smooth_mask()` 按「局部平不平」给权重 —— 平坦处动、细节处不动，
   细节还要往外膨胀一圈。这是整套效果里最关键的一道保险：与其猜「这是海还是城市」
   （猜错一次整栋楼就游起来），不如按像素看平不平。

### 13.2 速度：先测量再改

1080p 单进程逐层计时（秒/帧）：`warp` 0.303、夜景灯光 0.139、光影 0.075、
低频场 ×4 约 0.040、`render` 合计 0.607。24 帧实测 1/2/4 进程分别
**17 / 15 / 16 秒**（并行几乎不提速，内存带宽已饱和）；纯编码 90 帧 **4.5 秒**；
把 PIL 的 F 模式 resize 换成 numpy 双线性后 `fx_light` 0.075→0.081 秒。
结论：**瓶颈是 1080p 全幅 float32 数组吞吐，不是 warp 次数、不是 PIL、不是编码。**

所以按上午的建议落地分辨率档位：

| 档 | 尺寸 | 实测 | 选法 |
|---|---|---|---|
| 默认 | 1600×900 | **29~31 秒** | 1080p 屏放大 1.2 倍，软化很轻 |
| 快 | 1280×720 | **20 秒** | 批量出片 |
| 原尺寸 | 1920×1080 | 42~47 秒 | `gen-motion.bat -MaxEdge 1920` |

代价：1600 档放大到 1920 与 1920 档首帧 PSNR **34.8 dB**（含放大与两次 H.264 编码差异），
细节略软。`-MaxEdge` 由 ps1 同时透传给 Python 引擎和 ffmpeg 兜底，两条路尺寸一致；
`Invoke-PythonEngine` 会往 `%APPDATA%\wallpaper\gen-motion.log` 写「引擎参数：长边=…」，排障先看这行。

顺带做了三项不损失画质的优化，但**它们不是提速主因**（合计只把 47 秒压到 42 秒）：
- **合并位移场**：天空/水面/中部呼吸/兜底微动全写进一张 `(dx,dy)`，遮罩直接乘进位场，
  每帧只 warp 一次（原 2~3 次）；
- **uint8 量化采样**：原图每帧相同，量化一次后 gather 内存流量降 4 倍，
  与 float32 版关键帧差 **0.000~0.003/255**；
- numpy 双线性上采样（插值系数按尺寸缓存）替换 PIL F 模式 resize。

### 13.3 首尾同帧：修掉一个真缺陷

重出片后抽首帧/末帧只有 **36.5 dB**，回查发现两处相位不是整数倍：
`flow_field` 的 `sin(yy/sy - ph*0.6)`、`fx_subject` 的 `sin(... + ph*1.6)`。
`ph = 2πk·t/T`，t=T 时 `-1.2π` / `3.2π` 回不到 0，循环点留下台阶。
改成 `-ph` / `ph*2.0` 后：

- render 层首尾差 **0.0000/255**（PSNR 166 dB，只剩浮点噪声），雨图同样成立；
- 成片首尾 **40.4 dB**（原 36.5 dB），余下 1.6/255 来自 x264 对 I 帧/P 帧的压缩差。
- **规则**：以后加任何时间项，相位系数必须是 `ph` 的整数倍。

### 13.4 雨景判定：不能放宽阈值

全库 17 张实测 `streak`：动漫线稿 1.21 / 1.13、浮空城 1.13，都比真雨景
`sleepy-rainy-evening` 1.10 / `rainy-cyberpunk-streets` 1.09 更高；
另试「细亮线密度」「梯度方向集中度」也分不开（浮空城细亮线 0.072，是雨图的两倍）。
放宽阈值到 1.05 会让 **5 张非雨图出现雨丝**。

改成确定性双通道（`analyze(img, hint)`，hint 传图片路径/id）：
1. 纯视觉强证据：`streak > 1.35 && lum < 0.58`（老规则保留）；
2. 语义线索 + 视觉佐证：`rain_hint(文件名)` 命中 `rain / drizzle / 雨`，
   且 `streak > 0.80 && lum < 0.62`。语义只降低证据门槛，不单独决定下雨。

### 14.2 根因：整幅原图每帧被亚像素重采样

先排除了两个想当然的原因：

| 怀疑 | 实测 | 结论 |
|---|---|---|
| 遮罩乘进位移场造成几何撕裂 | 位移场水平相邻跳变 p99 **0.65px**、最大 2.01px；sky 遮罩跳变 p99 0.056 | 不是 |
| H.264 8×8/16×16 宏块 | 列梯度按 8 相位峰谷比 **1.098**、行 1.048 | 不是 |

真凶是 `warp(img, dx, dy)` 对**整幅原图**做双线性重采样。定量：

```
均匀位移 0.00px → 高频能量 6.014（100%）
          0.25px → 5.196（ 86.4%）   ← 糊掉 13.6%
          0.50px → 4.875（ 81.1%）   ← 糊掉 18.9%
          1.00px → 6.013（100%）     ← 整数位移精确复制，不糊
```

位移场随时间在 0↔1px 之间连续摆动，星点 / 云絮 / 云海泡沫 / 草叶就
**一帧清、一帧糊、一帧又清**地闪——播放时正是「碎块 / 马赛克」观感。
静态帧看不出来，所以之前几轮目视对比都没抓到。

### 14.3 v3 的五项改动（全在 `tools/gen-motion.py`）

1. **高频锁定**：新增 `lowpass()` / `_low_cached()`。只对低通图（GaussianBlur 2px）做 warp，
   把 `delta = flowed - low` 按软区域权重加回原图。结构细节逐像素来自原图，
   **永不重采样** → 不再糊、不再闪。
2. **内容演化**：新增 `evolution_field()` / `content_evolution()`。6 组多尺度行波 +
   原地脉动（`k=0` 项）让云 / 雾 / 水面的明暗自己流动、翻卷、生成消散，
   不是把像素从别处搬过来。全部时间项为 ph=2πt/T 的整数倍，首尾严格同帧。
3. **连续场**：`blur_field()` 用 F 模式小网格缩放平滑位移场；遮罩改为只乘在变化量上，
   不再乘进位移场；`soft_region()` 做区域级大幅平滑，去掉块状边界。
4. **柔化粒子**：雨丝层过 0.6px 高斯，1px 硬线变成半透明水丝，不再像划痕/噪点。
5. **编码**：`crf 17 / medium` → `crf 14 / slow / -tune animation`，压掉低码率块效应。

`analyze()` / `rain_hint()` / `--analyzetest` / CLI / ps1 参数一律未动，
`--MaxEdge 1280|1920` 仍可覆盖。
